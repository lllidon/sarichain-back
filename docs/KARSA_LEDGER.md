# دفتر کل کارسا

## سیاست مصوب
- کاهش سالانه: ۰٫۲٪ از مانده مصرف‌نشده.
- نرخ ماهانه مرکب: `1 - (1 - 0.002)^(1/12)` = حدود ۰٫۰۱۶۶۸۲٪.
- زمان اعمال: ماهگرد هر واریز مستقل.
- مصرف: FIFO؛ قدیمی‌ترین سهمیه ابتدا مصرف می‌شود.
- نرخ تومان/کارسا در تنظیمات مدیریت ثبت و در هر تراکنش snapshot می‌شود.
- نرخ تبدیل اولیه عمداً خالی است و باید توسط مدیریت تنظیم شود.

## مدل داده
- `members.karshaBalance`: موجودی تجمیعی سازگار با پروفایل‌های فعلی.
- `karsha_wallet_lots`: سهمیه‌های واریز با مانده، زمان ایجاد، anchor و شمارنده ماهگرد.
- `karsha_ledger`: دفتر کل رویدادهای افزایش، کاهش، مهاجرت موجودی، هدیه و استهلاک.
- `karsha_policy`: نرخ تبدیل و سیاست ثابت کاهش.

## چرخه عملیات
1. افزایش اعتبار یک Lot و یک Ledger Entry در یک تراکنش MongoDB می‌سازد.
2. کاهش اعتبار سهمیه‌ها را به ترتیب تاریخ واریز مصرف می‌کند و allocation هر Lot را ثبت می‌کند.
3. در هر ماهگرد، فقط مانده همان Lot کاهش می‌یابد؛ بخش مصرف‌شده دوباره مشمول کاهش نمی‌شود.
4. اجرای مجدد عملیات با idempotency key تکرار مالی ایجاد نمی‌کند.
5. موجودی‌های قدیمی بدون Lot، در نخستین همگام‌سازی به‌عنوان `legacy_migration` منتقل می‌شوند؛ کاهش گذشته‌نگر اعمال نمی‌شود.
6. سرویس هنگام شروع و سپس هر ۶ ساعت، ماهگردهای سررسیدشده را پردازش می‌کند. همچنین هنگام مشاهده کیف پول و عملیات مالی، سررسیدهای همان عضو به‌روز می‌شوند.

## API
- `GET /web/karsha`: موجودی، نرخ، Lotها و ۲۰ تراکنش آخر.
- `GET /web/karsha/transactions?page=1`: تاریخچه صفحه‌بندی‌شده عضو.
- `GET /organization/karsha-policy`: سیاست و نرخ.
- `POST /organization/karsha-policy`: ذخیره نرخ تومان هر کارسا.
- `GET /organization/karsha-ledger`: دفتر کل مدیریت.
- `POST /organization/karsha-adjustments`: افزایش/کاهش دستی با علت و شناسه یکتا.
- `POST /organization/karsha-decay/sweep`: اجرای دستی پردازش ماهگردهای سررسیدشده.

## پیش‌نیاز پایگاه داده
عملیات چندسندی دفتر کل با MongoDB transaction انجام می‌شود؛ بنابراین MongoDB باید Replica Set یا MongoDB Atlas باشد. در MongoDB standalone، عملیات مالی به‌صورت امن رد می‌شود و هیچ تغییر ناقصی ثبت نمی‌کند.

## مرزهای فعلی
- ثبت جایزه تکمیل مدارک در دفتر کل انجام می‌شود.
- API و سرویس FIFO برای بدهکارکردن کارسا آماده‌اند.
- اتصال بدهکارکردن به پرداخت سفارش/تبدیل واقعی به تومان عمداً تا تعیین نقطه قطعی تسویه انجام نشده است؛ ایجاد سفارش به‌تنهایی اثبات پرداخت نیست و نباید موجودی را کم کند.
